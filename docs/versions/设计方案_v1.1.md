# 旅游团身份证登记 App — 设计方案 v1.1

> 目标：安卓手机上离线完成「新建旅行团 → 批量选身份证照片 → 自动提取姓名/性别/身份证号 → 人工兜底核对 → 打标签备注 → 导出 xlsx/txt → 分享微信」。
> 硬约束：客人的身份证信息一次都不出手机。
> v1.1 变更：登记日期改为 App 内字段且不导出；原图绝不改动、临时件即用即删；去掉保单号/房型/护照列，加备注与标签；明确多人装机与升级策略；模型定为 `gpt-6-astra`。

---

## 0. 一句话结论

**Android 原生（Kotlin + Compose）+ 打包版 ML Kit 中文 OCR + 三通道扰动识别 + 身份证号 MOD 11-2 校验位 + 自写最小 xlsx 生成器 + FileProvider 分享**。APK 不声明 INTERNET 权限——不是承诺不上传，是进程连 socket 都建不出来。工期 4–5 个工作日到能装机版。

## 1. 技术栈

原生而不是 Flutter/小程序：这活的命脉全在原生层（相册选择器、离线 OCR 绑定、FileProvider 分享），套一层跨平台只会增加排查成本，而界面就四页、没有复杂动效。

- `minSdk 24`（Android 7.0，照顾同事的旧手机）、`targetSdk 35`、Kotlin 2.x、JDK 17、AGP 8.x、Gradle 8.x
- `:app`（UI）+ `:core-ocr`（识别与解析）+ `:core-export`（表格生成），后两个是纯 Kotlin 库，单测在 JVM 上跑，不开模拟器

### 1.1 OCR 引擎：必须是打包版

| 依赖 | 模型位置 | 离线首跑 | 需要 GMS |
|---|---|---|---|
| `com.google.mlkit:text-recognition-chinese:16.0.1` | APK 内（+15–20 MB） | ✅ | ❌ 不需要 |
| `com.google.android.gms:play-services-mlkit-text-recognition-chinese` | 运行时从 Play 服务下载 | ❌ | ✅ 需要 |

同事的手机大概率是国产机，很多没有 GMS。选第二条线不光可能在同事手机上直接不可用，首次识别还要联网下模型，正好踩红线。锁死第一条。

## 2. 三次识别怎么才有意义（核心技术点）

同一张图、同一个引擎连跑三次，结果一模一样，包括错的地方。所以三次必须是**三种不同的输入条件**：

| 通道 | 预处理 | 模拟场景 |
|---|---|---|
| A | 原图 → 卡面定位/透视校正 → 裁出号码行带 → 放大到长边 ≥1600 px | 正常拍摄，求最好那次 |
| B | 灰度 → CLAHE 局部对比增强 → 自适应阈值二值化 | 塑料卡反光、磨砂贴膜、花纹背景 |
| C | 旋转 +1.2° → 2× 上采样 → 轻锐化 | 手略歪、对焦偏软 |

三份结果按"号码段 / 姓名段 / 日期段"分区后各自归一化（全角转半角、去空格、数字段内做 `O Q D→0`、`I l |→1`、`Z→2`、`S→5`、`B→8`、`G→6`；**姓名段绝不做这个映射**，否则「吕」会被改坏），再逐字段比对。

判定规则（三字段各不相同）：

- **身份证号**：三份一致 **且** 通过 ISO 7064 MOD 11-2 校验位 → 自动通过。**校验位不过一律人工**，不管三次多一致——反光盖掉一位、三次补成同一个数字这种情况，只有校验位抓得住。
- **性别**：**不 OCR**。从号码第 17 位奇偶推（奇男偶女），零成本零错误。
- **出生日期**：从号码 7–14 位推，OCR 出的"出生"栏只做交叉提示，不改号。
- **姓名**：三份一致 + 2–4 个汉字 + 落在「姓名」二字锚点右/下邻接区 + 全字在 GB2312 常用字表内 → 自动通过；生僻字/少数民族用字一律人工。

## 3. 数据模型

```
Team    团
  id, name, teamCode, departDate, note, createdAt

Member  成员
  id, teamId, seq
  name, gender, idNumber, birthDate
  registeredAt          // 登记时间：处理当时（精确到分钟），仅 App 内显示，不导出
  status                // AUTO_OK | NEED_REVIEW | MANUAL_OK | OCR_FAILED
  note                  // 自由备注
  createdAt, updatedAt

Tag     标签（全局库，非按团）
  id, label, colorIndex, isPreset, sortOrder
MemberTag  多对多：memberId, tagId
```

**预设标签**：孕妇、高龄（65+）、儿童、免票、半票、退伍军人、残障、素食、清真。用户可增删改，也可随手新建（输入即建）。

**导出列**：`序号 | 姓名 | 性别 | 身份证号 | 出生日期 | 备注 | 标签`。
登记时间不进导出（按你说的，它只是 App 内方便用的字段）。标签列默认带上——班次分票、住宿分房都用得上；导出确认页可以勾掉。

**约束**：同团内身份证号重复 → 黄条警告"该号码已在团内第 3 位"，不硬拦（同名同证件真有可能重复登记，得人来判断）。

## 4. 临时文件与相册：一寸都不碰用户的相册

这是 v1.1 明确的一条硬规矩：

1. **相册原图只读**。通过 Photo Picker / SAF 拿到的是只读 URI，App 全程只读不写，识别结束也不删除、不移动、不改名。用户相册里那张照片跟没被碰过一样。
2. **所有中间产物都在 `cacheDir` 里**，路径形如 `cacheDir/work/<uuid>/`：透视校正后的图、二值化图、旋转图、号码区裁片。`cacheDir` 属于应用私有沙盒——不出现在相册、不被文件管理器默认看到、不占用户可见存储，系统空间紧张时还会被自动回收。
3. **即用即删**：每张图识别完（不论成功失败）立刻删该 uuid 目录下的全部文件，异常路径也要走 `finally` 清理。一次处理 50 张，处理后 `cacheDir/work` 应为 0 字节。
4. **绝不调用 MediaScanner / MediaStore 写入**，绝不往 `Pictures/`、`DCIM/`、`Download/` 写任何东西。
5. 待人工核对的那几张，只在**应用私有目录**（`filesDir/review/`，同样不可见）留一张号码区小图（约 100 KB），确认后即时删除。可以在设置里关掉（关掉后核对页只显示三份文字候选，没有图）。

> 一句话：用户手机里能看见的东西，一张不多也一张不少。

## 5. 界面（给 Claude 的 brief）

四页 + 一个导出确认页。定位不是潮玩 App，是旅行社前台在强光下、单手、一次处理三十个人的工具。

1. **团列表**：卡片流。团名、人数、待核对红点、出发日期。右下 FAB 新建团。支持左右滑动删除（带二次确认）。
2. **录入页**：顶部「批量选择照片」（多选上限 100 张），下方处理队列逐条显示缩略图、已识别的姓名/号码、状态徽标。底部常驻「继续添加 / 去核对(n) / 导出」。
3. **核对页**：上半是号码区放大图（双指缩放、左右滑切人），下半是三份候选对照，点候选即填、也可直接改键盘。分歧字段琥珀色高亮并自动聚焦。底部常驻「确认并下一条」。
4. **成员表**：序号/姓名/性别/号码/状态，顶部按标签筛选（多选，AND/OR 可切），行内编辑，长按删除，搜索。
5. **导出确认页**：表格预览（前 5 行 + 总行数）、列勾选、xlsx/txt 选择、文件名（默认 `{团名}_{YYYYMMDD}`）、「导出后清空本团」开关，点确认才生成。

**设计约束**：正文 ≥16sp、按钮 ≥48dp、主操作放拇指弧内；背景暖白 `#FDFBF7`、主色深靛蓝 `#1F5AA6`、状态色只有灰/绿/琥珀三档；不用渐变、不用玻璃拟态、不用大面积插画；号码用等宽数字（tnum）并分组显示 `110101 19900101 1234`。暗色模式 v1 不做（户外强光下没人用）。

> 这套是"干净克制"的专业工具语言，跟你平时偏好的奶油低饱和治愈系是两套东西。工具类 App 我建议不要带治愈风。

## 6. 导出

### 6.1 xlsx：自己写，不引 POI

POI 在安卓上要开 desugar、方法数爆表、包体 +12 MB，而我们要的只是一个 sheet 七列文本。直接 `ZipOutputStream` 拼 OOXML（`[Content_Types].xml`、`_rels/.rels`、`xl/workbook.xml`、`xl/worksheets/sheet1.xml`、`xl/styles.xml`），单元格全走 `inlineStr`，约 250 行 Kotlin，零依赖，可在 JVM 上单测。

**必踩的坑**：18 位身份证号会被 Excel 当数值显示成 `1.10101E+17`。必须给该列设文本格式（numFmt `@`）。导出后我会用 `openpyxl` 读回来断言 `type(cell.value) is str` 且长度 18，这是验收项。

### 6.2 txt：UTF-8 带 BOM

`\uFEFF` 开头 + Tab 分隔 + CRLF。不带 BOM 的话微信里用手机记事本打开就是乱码。

### 6.3 分享微信

```kotlin
val uri = FileProvider.getUriForFile(ctx, "$packageName.fileprovider", file)
Intent(Intent.ACTION_SEND).apply {
    type = "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet" // txt 用 text/plain
    putExtra(Intent.EXTRA_STREAM, uri)
    addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)
}
```

微信能直接收 xlsx 并内置预览，也能发文件传输助手。别用 `type="*/*"`（部分版本会拒）。分享是把 URI 交给微信 App，联网的是微信——所以"零 INTERNET 权限"和"能发微信"不冲突。

## 7. 安全

1. **不声明 INTERNET 权限**。进程建不了 socket，用户在设置里看到网络权限是"无"，可以当场给客户验。
2. **不申请存储权限**：新版走 Photo Picker，Android 11 以下走 SAF，拿到的是一次性只读 URI。
3. **ML Kit 打包版**：模型在 APK 内，运行时不下载、不联网校验。
4. **数据只落应用私有目录**，其他 App 读不到（分区存储）。
5. **相册原图不动**，中间产物即用即删（见第 4 节）。
6. **一键清空本团** + 「导出成功后自动清理」开关。
7. 不接任何崩溃上报（无 Firebase/Crashlytics）。
8. 可选（v1.1 建议做）：**启动 PIN 锁**——手机落在桌上被同事翻开就能看到一屏身份证号，四位 PIN 加一层，输错 10 次触发清空。要不要做你定。

**验收**：`aapt dump permissions app-release.apk` 里不能出现 INTERNET；飞行模式下全流程走完。

## 8. 给同事用：签名、升级、数据

- **固定 keystore**（`release.keystore`），生成后连同密码一起备份到两处。签名一变，同事手机上就只能卸载重装、数据全丢。
- **包名固定** `com.<你的域名>.tourid`，版本号 `versionCode` 单调递增、`versionName` 用 `1.0.x`。
- **升级不能丢数据**：Room 每次改表都要写 Migration 并测「装旧版 → 灌数据 → 覆盖装新版 → 数据还在」。这条写进每次发版清单。
- **分发**：APK 直接传（企业微信/QQ/数据线），安装时手动允许"未知来源"。微信直接发 apk 会被拦或提示风险，实际用企业微信或前置传输。不上架商店。
- **数据不互通**（必须让同事们知道）：不联网就没有同步，每人手机里各存各的团。要汇总，就是各自导出 xlsx 发到群里合并。如果需要，v2 可以做**局域网直连同步**（手机热点 + 同一 WiFi 下互传，不经过任何服务器），但 v1 不做。

## 11. 验收清单

1. 20 张真证测试集：**自动通过率 ≥85%**，**误通过率（自动通过但号码错）= 0**。误通过是红线，宁可全进人工。
2. `aapt dump permissions` 无 INTERNET；飞行模式全流程能走完。
3. 处理完 50 张后 `cacheDir/work` 为空；相册原图字节级未变（比对 size + mtime）。
4. 导出的 xlsx 用 openpyxl 回读：号码是 `str` 且 18 位；txt 微信打开不乱码。
5. 无 GMS 机型（或 AOSP 模拟器）OCR 正常。
6. 覆盖安装旧版到新版数据不丢（Room Migration 测试）。
7. 一次 50 张不 OOM（峰值 <300 MB）。
8. 灭屏、切后台、断网回来队列不丢。

## 12. 风险与边界

- 反光/贴膜/斜拍的号码行：三通道 + 校验位兜大半，真实自动通过率 80–90%，别按 100% 设计流程。
- 一图多证：v1 不做切分，识别出多组号码直接标 FAILED 让人工录。
- 生僻字姓名：一律人工。
- 同事手机系统版本跨度大：`minSdk 24` 要在 Android 7、10、14 各跑一遍。
- 不上架商店，无自动更新：新版靠人工发 APK。
